# Scrum no projeto

Este projeto é individual, então acumulo os três papéis do Scrum Team:
Product Owner, Scrum Master e Developer. Uso o Scrum de forma adaptada
para praticar os artefatos e eventos enquanto estudo para a certificação.

## Compromissos

**Meta do Produto:** ter uma central de conhecimento que documente sistemas,
regras, pessoas e acessos, com testes que confirmem cada procedimento.

**Meta da Sprint 1:** ter o ambiente pronto e a primeira versão do banco
do dicionário de dados funcionando.

**Definição de Pronto:** um item só está pronto quando funciona e tem uma
nota explicando o que foi feito, como e por quê.

## Sprint 1

| Item do backlog | Situação |
|---|---|
| Instalar SQL Server e SSMS | ✅ Feito |
| Modelo conceitual | ✅ Feito |
| Modelo lógico (colunas e chaves) | 🔄 Em andamento |
| Criar o banco | ✅ Feito |
| Criar as tabelas | 🔄 4 de 9 prontas |
| Inserir dados de exemplo | ⏳ A fazer |
| Primeira consulta no catálogo do banco | ⏳ A fazer |
| Nota no repositório | ⏳ A fazer |

## Adaptações

- O modelo lógico foi feito junto com a criação das tabelas, em vez de
  ser uma etapa separada. Decisão registrada para a Retrospectiva.

## Como os eventos funcionam aqui

- **Sprint Planning:** ordenação do backlog no início da Sprint.
- **Daily:** no início de cada sessão, uma frase sobre o que fiz,
  o que vou fazer e o que está me travando.
- **Sprint Review:** apresentação do que foi construído ao fim da Sprint.
- **Retrospectiva:** o que funcionou, o que não funcionou e o que mudar.
